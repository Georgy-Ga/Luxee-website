# Spambot: Лимит рассылки и отображение аккаунта

**Дата:** 20.07.2026
**Статус:** ✅ Завершено

## Обзор изменений

Добавлена валидация лимита рассылки (максимум 30) и отображение Luxee аккаунта в истории рассылок.

## 1. Лимит рассылки: максимум 30

### Проблема
- Не было ограничения на количество рассылок
- Пользователь мог вводить любое число (например, 1000+)
- Отсутствовала валидация на backend

### Решение

#### 1.1 Backend валидация (SpambotService.js)

```javascript
// Константа
const MAX_DISTRIBUTION_LIMIT = 30;

// Валидация в startDistribution()
if (!config.limit || config.limit < 1 || config.limit > MAX_DISTRIBUTION_LIMIT) {
    throw new Error(`Distribution limit must be between 1 and ${MAX_DISTRIBUTION_LIMIT}`);
}
```

**Файл:** `backend/src/services/SpambotService.js`

**Изменения:**
- Добавлена константа `MAX_DISTRIBUTION_LIMIT = 30`
- Валидация выполняется **перед** проверкой доступа к аккаунту
- Возвращается четкая ошибка если лимит превышен

#### 1.2 Frontend валидация (DistributionForm.jsx)

```javascript
const MAX_DISTRIBUTION_LIMIT = 30;

// Input с автоматическим ограничением
<input
    type="number"
    value={limit}
    onChange={(e) => {
        const value = parseInt(e.target.value) || 1;
        setLimit(Math.min(Math.max(value, 1), MAX_DISTRIBUTION_LIMIT));
    }}
    min="1"
    max={MAX_DISTRIBUTION_LIMIT}
    className="..."
/>
```

**Файл:** `frontend/src/components/Spambot/DistributionForm.jsx`

**Изменения:**
- Константа `MAX_DISTRIBUTION_LIMIT = 30`
- Значение по умолчанию изменено с `50` на `30`
- Input автоматически ограничивает значение через `Math.min()` и `Math.max()`
- Добавлен атрибут `max={MAX_DISTRIBUTION_LIMIT}`
- Подсказка под полем: "Максимум 30 рассылок"
- Label обновлен: "Лимит на рассылку (макс. 30)"

### Как это работает

**Frontend защита:**
1. Пользователь не может ввести число > 30 (автоматически обрезается)
2. HTML атрибут `max="30"` предотвращает ввод через стрелки
3. `onChange` хендлер принудительно ограничивает значение

**Backend защита:**
```javascript
// Даже если пользователь изменит HTML через DevTools
if (config.limit > 30) {
    throw new Error('Distribution limit must be between 1 and 30');
}
```

### Безопасность
✅ Невозможно обойти через F12 / DevTools  
✅ Backend всегда проверяет лимит  
✅ Возвращается понятная ошибка пользователю

## 2. Отображение Luxee аккаунта в истории

### Проблема
- В истории рассылок не было видно на каком Luxee аккаунте запущена рассылка
- Сложно ориентироваться когда у пользователя несколько аккаунтов
- Невозможно быстро определить какой аккаунт использовался

### Решение

#### 2.1 Backend уже возвращает accountEmail

**Файл:** `backend/src/services/SpambotService.js`

Методы `getUserDistributions()` и `getAllDistributions()` уже возвращают:

```javascript
{
    id: d._id,
    distributionId: d.distributionId,
    status: d.status,
    accountEmail: d.luxeeAccount.luxeeEmail, // ✅ Уже есть
    profileName: d.config.profileName,
    // ...
}
```

**Совместимость:** ✅ Изменений в базе данных не требуется

#### 2.2 Frontend отображение (DistributionHistory.jsx)

**Файл:** `frontend/src/components/Spambot/DistributionHistory.jsx`

**Изменения в таблице:**

```jsx
<thead>
    <tr>
        <th>Дата</th>
        <th>Аккаунт</th>        {/* ← НОВОЕ */}
        <th>Профиль</th>
        <th>Тип</th>
        <th>Статус</th>
        <th>Отправлено</th>
        <th>Пропущено</th>
        <th>Действия</th>
    </tr>
</thead>
<tbody>
    {distributions.map(dist => (
        <tr>
            <td>{formatDate(dist.createdAt)}</td>
            <td>                                {/* ← НОВОЕ */}
                <div className="max-w-[180px] truncate" title={dist.accountEmail}>
                    {dist.accountEmail || 'N/A'}
                </div>
            </td>
            <td>{dist.profileName}</td>
            {/* ... */}
        </tr>
    ))}
</tbody>
```

**Особенности:**
- Колонка "Аккаунт" идет **после** "Дата" и **перед** "Профиль"
- Максимальная ширина `180px` с обрезкой (`truncate`)
- Полный email показывается в `title` при наведении
- Fallback на `'N/A'` если email отсутствует

   - Ввести `15` → ✅ Работает

### Проверить отображение аккаунта
