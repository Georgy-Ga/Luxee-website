# AI Adaptive Delay Implementation

**Дата:** 23 июля 2026  
**Версия:** 1.1  
**Статус:** ✅ Реализовано + Critical Fix

---

## 📋 Обзор

Реализована система **адаптивных задержек** для AI автоответов, которая учитывает время ожидания сообщения и оптимизирует скорость ответа, соблюдая при этом реалистичные временные рамки.

---

## 🎯 Цели

1. **Уменьшить общее время ответа** при обработке множественных сообщений
2. **Соблюдать реалистичные временные рамки**: 25-59 секунд от получения сообщения
3. **Ускорить ответ на старые сообщения** (висят 50+ секунд)
4. **Не затрагивать Catch Up** (оставить стандартную логику)

---

## 🔄 Логика Работы

### **Для ОБЫЧНЫХ чатов (не Catch Up):**

```
1. Получаем elapsed = Date.now() - chat.lastActivity
2. Генерируем случайную целевую задержку: 7-13 секунд
3. Вычисляем: calculatedDelay = targetDelay - elapsed

4. Применяем правила:

   ЕСЛИ elapsed >= 45 секунд:
      → СРОЧНЫЙ РЕЖИМ: задержка = 500ms
      
   ИНАЧЕ ЕСЛИ (elapsed + calculatedDelay) < 25 секунд:
      → РЕАЛИСТИЧНЫЙ РЕЖИМ: задержка = (25 секунд - elapsed)
      
   ИНАЧЕ:
      → АДАПТИВНЫЙ РЕЖИМ: задержка = max(500ms, calculatedDelay)
```

### **Для CATCH UP:**

```
Обычная случайная задержка: 7-13 секунд (БЕЗ адаптивной логики)
```

## 📊 Примеры Работы

### **Case 1: Свежее сообщение (2 секунды назад)**

```
elapsed = 2s
targetDelay = 10s (случайное 7-13)
calculatedDelay = 10s - 2s = 8s
projectedTime = 2s + 8s = 10s < 25s ❌

→ Ждём: 25s - 2s = 23 секунды
→ ИТОГО: Ответ через 25 секунд от получения ✅
```

### **Case 2: Среднее (15 секунд назад)**

```
elapsed = 15s
targetDelay = 9s
calculatedDelay = 9s - 15s = -6s
projectedTime = 15s + 0s = 15s < 25s ❌

→ Ждём: 25s - 15s = 10 секунд
→ ИТОГО: Ответ через 25 секунд от получения ✅
```

### **Case 3: Старое (30 секунд назад)**

```
elapsed = 30s
targetDelay = 11s
calculatedDelay = 11s - 30s = -19s
projectedTime = 30s >= 25s ✅

→ Ждём: max(0.5s, -19s) = 0.5 секунды
→ ИТОГО: Ответ через 30.5s + 4s (AI) + 5s (send) = 39.5s ✅
```

### **Case 4: СРОЧНОЕ (50+ секунд назад)**

```
elapsed = 55s
→ СРОЧНЫЙ РЕЖИМ!
→ Ждём: 500ms

→ ИТОГО: Ответ через 55.5s + 4s (AI) + 5s (send) = 64.5s ⚠️
(Не уложились в 59s, но это лучшее что можно сделать)
```

## 📝 Примечания

### **Источник времени:**

Используется `chat.lastActivity` из API Luxee - это **timestamp последней активности** в чате (когда мужчина отправил сообщение).

**Важно:** Это значение **НЕ меняется** при сканировании профилей, поэтому **безопасно** использовать для расчётов.

### **Почему 25 секунд минимум?**

Это **реалистичное время**, за которое человек:
1. Получает уведомление (1-5s)
2. Открывает приложение (3-10s)
3. Читает сообщение (5-10s)
4. Печатает ответ (10-15s)

**Итого: 19-40 секунд** - мы взяли **25 секунд** как безопасный минимум.

### **Почему 50 секунд порог срочности?**

Платформа Luxee требует ответа в течение **59 секунд** для получения оплаты.

С учётом:
- AI генерация: 4-5s
- Отправка: 5-7s
- Overhead: 2-3s

Если сообщение уже висит **50+ секунд**, нужно отвечать **максимально быстро** (500ms задержка), иначе не уложимся в 59s.
