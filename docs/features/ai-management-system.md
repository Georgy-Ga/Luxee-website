# AI Management System - Полная документация

## 🎯 Цели системы

### 1. Управление AI
- **Админ** может включать/выключать AI для:
  - Всего пользователя (глобально)
  - Конкретного Luxee аккаунта
- **Пользователь** может только ВЫКЛЮЧИТЬ AI (не включить)
- **По умолчанию** AI выключен для новых аккаунтов

### 2. Многопоточность (отдельный контекст для AI)
- AI работает в отдельном браузерном контексте
- Не блокирует действия пользователя
- Пользователь и AI могут работать параллельно

### 3. Проверка статуса AI
- Перед отправкой ответа проверяем не выключил ли пользователь AI
- Если выключил - отменяем отправку

### 4. История сообщений
- Пользователь видит последние 5 сообщений
- AI получает только последнее сообщение для контекста

## 📊 Архитектура

### Модели данных

#### UserModel
```javascript
{
  aiEnabled: Boolean (default: true),        // Пользователь сам выключает
  aiEnabledByAdmin: Boolean (default: true)  // Админ управляет
}
```

#### LuxeeAccountModel
```javascript
{
  aiEnabled: Boolean (default: false),  // AI для конкретного аккаунта
  aiContext: String                     // ID отдельного браузерного контекста для AI
}
```

### Логика проверки AI

```javascript
function canUseAI(user, luxeeAccount) {
  return user.aiEnabled &&           // Пользователь не выключил
         user.aiEnabledByAdmin &&    // Админ разрешил
         luxeeAccount.aiEnabled;     // AI включен для аккаунта
}
```

## 🔧 Компоненты системы

### Backend

#### 1. AI Browser Context Service
- Создает отдельный контекст для каждого Luxee аккаунта с AI
- Использует существующую сессию (не требует повторной авторизации)
- Работает параллельно с основным контекстом пользователя

#### 2. AI Management Service
- Управление AI статусом для пользователей и аккаунтов
- Проверка прав доступа (только админ включает)
- API для получения статуса AI

#### 3. AI Response Service (обновленный)
- Проверяет статус AI перед генерацией
- Проверяет статус AI перед отправкой
- Загружает последнее сообщение для контекста
- Отправляет через отдельный контекст

### Frontend

#### 1. AI Management Panel (только админ)
Вкладка в настройках после "Пользователи":
- Список всех пользователей
- Для каждого пользователя:
  - Переключатель AI для всего пользователя
  - Список его Luxee аккаунтов
  - Переключатель AI для каждого аккаунта

#### 2. User AI Control
- Пользователь видит свой AI статус
- Может выключить AI (кнопка "Выключить AI")
- Не может включить если админ запретил
- Видит статус для каждого своего Luxee аккаунта

## 📝 API Endpoints

### AI Management (только админ)
- `GET /api/ai/users` - список пользователей с AI статусом
- `POST /api/ai/users/:userId/toggle` - вкл/выкл AI для пользователя
- `GET /api/ai/accounts` - список всех Luxee аккаунтов с AI
- `POST /api/ai/accounts/:accountId/toggle` - вкл/выкл AI для аккаунта

### User AI Control
- `GET /api/ai/my-status` - мой AI статус
- `POST /api/ai/my-toggle` - выключить свой AI
- `GET /api/ai/my-accounts` - мои аккаунты с AI статусом
- `POST /api/ai/my-accounts/:accountId/toggle` - выключить AI на аккаунте

## 🔐 Безопасность

1. **Права доступа:**
   - Только админ может ВКЛЮЧАТЬ AI
   - Пользователь может только ВЫКЛЮЧАТЬ
   - Middleware проверяет роль перед действием

2. **Проверки перед отправкой:**
   - Проверка AI статуса пользователя
   - Проверка AI статуса аккаунта
   - Проверка прав админа

3. **Изоляция контекстов:**
   - AI контекст изолирован от пользовательского
   - Нет конфликтов при параллельной работе

## 📈 Оптимизация

1. **Отдельный контекст для AI:**
   - Не блокирует действия пользователя
   - Параллельная обработка запросов
   - Использует существующую сессию

2. **Кэширование:**
   - Кэш AI статуса пользователей
   - Кэш контекстов браузера
   - Обновление при изменениях

3. **История сообщений:**
   - Загружаем только нужное количество
   - Пользователь: 5 последних
   - AI: 1 последнее

## 🔄 Workflow

### Сценарий 1: Админ включает AI
1. Админ открывает "Управление ИИ"
2. Выбирает пользователя
3. Включает AI для пользователя
4. Включает AI для конкретного Luxee аккаунта
5. Система создает отдельный контекст для AI
6. AI начинает работать

### Сценарий 2: Пользователь выключает AI
1. Пользователь видит что AI включен
2. Нажимает "Выключить ИИ"
3. Система проверяет текущие AI запросы
4. Отменяет неотправленные ответы
5. AI останавливается

### Сценарий 3: AI отвечает на сообщение
1. Приходит новое сообщение
2. Система проверяет AI статус (user + account)
3. Если включен - генерирует ответ в отдельном контексте
4. Перед отправкой снова проверяет статус
5. Если все еще включен - отправляет
6. Если выключен - отменяет отправку
