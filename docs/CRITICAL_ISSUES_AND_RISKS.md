## 🔴 КРИТИЧЕСКИЕ ПРОБЛЕМЫ (Приоритет 1) - МОГУТ СЛОМАТЬ СИСТЕМУ

### 1. Race Conditions в Browser Service
**Файл**: `backend/src/services/browser/browserService.js`

**Проблема**:
```javascript
// Строка 23-27: Проверка и установка блокировки НЕ атомарны
while (this.locks.get(accountId)) {
    await this.queues.get(accountId);
    await new Promise(resolve => setTimeout(resolve, 100));
}
this.locks.set(accountId, true); // ⚠️ Между проверкой и установкой может пройти другой запрос
```

**Что сломается**:
- При 100 пользователях с множественными аккаунтами (допустим 200-300 аккаунтов)
- Одновременные запросы к одному аккаунту могут пройти проверку одновременно
- Результат: дублирование контекстов, конфликты сессий, краш браузера

**Вероятность**: 95% при нагрузке
**Влияние**: Полный отказ системы

**Решение**:
```javascript
// Использовать семафоры или мьютексы
const locks = new Map(); // accountId -> Promise

async executeInQueue(accountId, fn) {
    const currentLock = locks.get(accountId) || Promise.resolve();
    const newLock = currentLock.then(async () => {
        try {
            return await fn();
        } finally {
            // Cleanup
        }
    });
    locks.set(accountId, newLock);
    return newLock;
}
```

### 2. Memory Leak в Browser Contexts
**Файл**: `backend/src/services/browser/browserService.js`

**Проблема**:
```javascript
// Строка 110: contexts.set(accountId, context);
// НЕТ автоматической очистки неактивных контекстов
```

**Что сломается**:
- 100 пользователей × 2-3 аккаунта = 200-300 контекстов
- Каждый контекст ~50-100MB памяти
- Итого: 10-30GB памяти только на контексты
- + AI контексты (еще ×2) = 20-60GB

**Вероятность**: 100%
**Влияние**: OOM (Out of Memory), краш сервера

**Решение**:
- Добавить TTL для неактивных контекстов (например, 30 минут)
- Автоматическая очистка при превышении лимита
- Мониторинг использования памяти

### 3. Отсутствие Rate Limiting для AI API
**Файл**: `backend/src/services/aiService/apiClient.js`

**Проблема**:
```javascript
// Строка 14-30: Нет ограничения на количество запросов
// При 100 пользователях с автоответами каждые 10 секунд
```

**Что сломается**:
- 100 пользователей × 3 аккаунта × 5 чатов = 1500 запросов каждые 10 секунд
- = 9000 запросов в минуту к AI API
- Omniroute/Gemini имеет лимиты (обычно 60-600 RPM)
- Результат: 429 Too Many Requests, блокировка API ключа

**Вероятность**: 100% при >20 активных пользователях
**Влияние**: Полный отказ AI функционала

**Решение**:
- Глобальная очередь с rate limiting (например, 10 запросов/сек)
- Exponential backoff при 429
- Приоритизация запросов (ручные > автоматические)

### 4. Параллельное восстановление сессий без ограничений
**Файл**: `backend/src/services/luxeeApi/luxeeAuthService/sessionService.js`

**Проблема**:
```javascript
// Строка 81-117: Promise.all без ограничения параллелизма
const restorePromises = accounts.map(async (account) => {
    await restoreSession({ userId, accountId });
});
const results = await Promise.all(restorePromises);
```

**Что сломается**:
- При старте сервера восстанавливаются ВСЕ аккаунты одновременно
- 300 аккаунтов × одновременное создание контекстов
- Браузер не выдержит, упадет с OOM или краш
- Playwright имеет лимит на количество одновременных контекстов

**Вероятность**: 100% при >50 аккаунтах
**Влияние**: Невозможность запуска сервера

**Решение**:
```javascript
// Использовать p-limit или аналог
import pLimit from 'p-limit';
const limit = pLimit(5); // Максимум 5 параллельных восстановлений

const restorePromises = accounts.map(account => 
    limit(() => restoreSession({ userId, accountId }))
);
```

### 5. Отсутствие транзакций в MongoDB
**Файл**: Все сервисы работающие с БД

**Проблема**:
```javascript
// Пример из aiAutoResponseService.js строка 298-311
// Сохранение в answeredChatService БЕЗ транзакции
await answeredChatService.saveAnsweredChat({...});
// Если здесь упадет - чат сохранен, но статус не обновлен
```

**Что сломается**:
- При сбоях между операциями данные становятся несогласованными
- Чат помечен как отвеченный, но AI не отправил сообщение
- Или наоборот - сообщение отправлено, но чат не помечен
- Результат: дублирование ответов или потеря данных

**Вероятность**: 70% при нагрузке
**Влияние**: Некорректная работа AI автоответов

**Решение**:
```javascript
const session = await mongoose.startSession();
session.startTransaction();
try {
    await answeredChatService.saveAnsweredChat({...}, { session });
    await account.save({ session });
    await session.commitTransaction();
} catch (error) {
    await session.abortTransaction();
    throw error;
} finally {
    session.endSession();
}
```

### 8. Отсутствие обработки ошибок Playwright
**Файл**: `backend/src/services/browser/pageHelpers.js`

**Проблема**:
```javascript
// Строка 11-18: Только логирование, нет retry
navigateTo: async ({ page, url, waitUntil = 'domcontentloaded', timeout = 30000 }) => {
    try {
        await page.goto(url, { waitUntil, timeout });
        return { success: true, url: page.url() };
    } catch (error) {
        console.error(`[Page Helper] Navigation error to ${url}:`, error.message);
        throw error; // ⚠️ Просто бросаем ошибку
    }
}
```

**Что сломается**:
- Сетевые сбои, таймауты, блокировки Luxee
- Одна ошибка навигации = падение всей операции
- Нет retry механизма
- При нагрузке частота ошибок возрастает

**Вероятность**: 90%
**Влияние**: Частые сбои операций

**Решение**:
```javascript
async navigateTo({ page, url, retries = 3 }) {
    for (let i = 0; i < retries; i++) {
        try {
            await page.goto(url, { waitUntil, timeout });
            return { success: true };
        } catch (error) {
            if (i === retries - 1) throw error;
            await new Promise(r => setTimeout(r, 1000 * (i + 1)));
        }
    }
}
```

### 9. Глобальная очередь сообщений - узкое место
**Файл**: `backend/src/services/browser/requestQueueService.js`

**Проблема**:
```javascript
// Строка 60-80: ВСЕ сообщения идут через одну очередь
async executeMessageSend(fn) {
    this.globalSendQueue = this.globalSendQueue.then(async () => {
        // Задержка 1 секунда между ЛЮБЫМИ сообщениями
        await new Promise(resolve => setTimeout(resolve, 1000));
    });
}
```

**Что сломается**:
- 100 пользователей отправляют сообщения
- Все идут через одну очередь с задержкой 1 сек
- Время ожидания = количество сообщений в очереди × 1 сек
- При 100 сообщениях в очереди = 100 секунд ожидания!

**Вероятность**: 100% при >10 активных пользователях
**Влияние**: Огромные задержки отправки

**Решение**:
- Очередь на аккаунт, а не глобальная
- Или пул очередей (например, 10 параллельных)
- Адаптивная задержка в зависимости от нагрузки

### 15. Отсутствие пагинации в API
**Файлы**: Все контроллеры возвращающие списки

**Проблема**:
```javascript
// UserController.js:93
getAllUsers: async () => {
    const users = await UserModel.find(); // ⚠️ Все пользователи сразу
    return users;
}
```

**Что сломается**:
- При 100 пользователях еще терпимо
- Но при росте - огромные ответы
- Медленная загрузка на фронтенде
- Перегрузка сети

**Решение**:
```javascript
getAllUsers: async (page = 1, limit = 20) => {
    const users = await UserModel.find()
        .skip((page - 1) * limit)
        .limit(limit);
    const total = await UserModel.countDocuments();
    return { users, total, page, pages: Math.ceil(total / limit) };
}
```
