## 1. Исправления в Backend

### 1.1 Модель LuxeeAccountModel

**Файл:** `backend/src/models/LuxeeAccountModel.js`

**Проблема:** Отсутствовало поле `aiEnabledByAdmin`, которое использовалось в коде

**Исправление:**
```javascript
aiEnabled: { type: Boolean, default: false }, // AI для этого аккаунта (пользователь может выключить)
aiEnabledByAdmin: { type: Boolean, default: false }, // Разрешил ли админ использовать AI (по умолчанию выключен)
```

**Логика работы:**
- `aiEnabledByAdmin` - контролируется только админом (по умолчанию `false`)
- `aiEnabled` - может переключать пользователь, но только если `aiEnabledByAdmin = true`
- AI работает только когда оба флага `true`

---

### 1.2 Сервис accountAiService

**Файл:** `backend/src/services/aiManagementService/accountAiService.js`

**Проблема:** Использовалось неправильное поле `userId` вместо `user` для связи с пользователем

**Исправления:**
- Изменено `userId` на `user` во всех запросах к базе данных
- Изменено `email` на `luxeeEmail` в select запросах
- Добавлен populate для поля `user` в `getAllAccountsAiStatus`

**Примеры исправлений:**
```javascript
// Было:
const accounts = await LuxeeAccountModel.find({ userId })

// Стало:
const accounts = await LuxeeAccountModel.find({ user: userId })
```

### 1.3 API методы

**Файл:** `frontend/src/api/aiApi.js`

## 3. Проверка AI Browser Context Service

**Файл:** `backend/src/services/browser/aiBrowserContextService.js`

### Подтверждённая функциональность:

✅ **Отдельные контексты для AI:**
- Создаётся отдельный браузерный контекст с ID `${accountId}_ai`
- Использует ту же сессию что и основной аккаунт
- Позволяет AI работать параллельно с пользователем

✅ **Автовосстановление:**
- Проверка здоровья контекста перед использованием
- Автоматическое пересоздание сломанных контекстов
- Восстановление после краха браузера

✅ **Управление жизненным циклом:**
- `createAiContext()` - создание нового AI контекста
- `getAiContext()` - получение существующего контекста
- `getOrCreateAiContext()` - получение или создание (основной метод)
- `closeAiContext()` - закрытие контекста
- `restoreAiContext()` - восстановление после перезапуска
- `restoreAllAiContexts()` - восстановление всех контекстов пользователя

✅ **Интеграция с AI Response Service:**
- AI отправляет сообщения через свой отдельный контекст
- Проверка разрешений перед отправкой
- Автоматическая отмена если AI был выключен во время генерации

## 4. Логика работы AI системы

### 4.1 Уровни контроля

1. **Уровень пользователя (UserModel):**
   - `aiEnabled` - пользователь сам включил/выключил AI
   - `aiEnabledByAdmin` - админ разрешил/запретил AI для пользователя

2. **Уровень аккаунта (LuxeeAccountModel):**
   - `aiEnabled` - пользователь включил/выключил AI для конкретного аккаунта
   - `aiEnabledByAdmin` - админ разрешил/запретил AI для конкретного аккаунта

### 4.2 Правила работы

**Для пользователя:**
- Админ может разрешить/запретить AI (`aiEnabledByAdmin`)
- Пользователь может только выключить AI, но не включить если админ запретил
- Формула: `canUserUseAi = user.aiEnabled && user.aiEnabledByAdmin`

**Для аккаунта:**
- Админ может разрешить/запретить AI для любого аккаунта
- Пользователь может выключить AI для своего аккаунта
- Пользователь НЕ может включить AI если админ запретил
- Формула: `canAccountUseAi = account.aiEnabled && account.aiEnabledByAdmin && canUserUseAi`

**По умолчанию:**
- Все новые пользователи: `aiEnabledByAdmin = true` (админ разрешил)
- Все новые аккаунты: `aiEnabledByAdmin = false` (админ НЕ разрешил)
- Это означает что AI нужно явно включать для каждого аккаунта

### 4.3 Отмена отправки

Если AI был выключен во время генерации ответа:
- Ответ генерируется
- Перед отправкой проверяется статус AI
- Если AI выключен - отправка отменяется
- Возвращается результат с флагом `cancelled: true`

## 5. Потенциальные проблемы и решения

### 5.1 Проблема: Контекст не создаётся

**Причины:**
- Нет sessionData у основного аккаунта
- Браузер не запущен или сломан
- Недостаточно ресурсов

**Решение:**
- Проверка наличия sessionData перед созданием
- Проверка здоровья браузера через `isBrowserHealthy()`
- Ожидание восстановления браузера (3 секунды)

### 5.2 Проблема: AI отправляет сообщения в основном контексте

**Причина:** Не используется `aiResponseService.sendResponse()`

**Решение:** Всегда использовать `aiResponseService.sendResponse()` который:
- Получает/создаёт AI контекст
- Проверяет разрешения
- Отправляет через AI контекст

### 5.3 Проблема: Контекст теряется после перезапуска

**Решение:** Использовать `restoreAiContext()` при:
- Запуске сервера
- Восстановлении после краха браузера
- Активации аккаунта
