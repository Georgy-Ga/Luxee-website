# 🔄 Возврат к предыдущей версии (без Docker)

Этот документ объясняет как вернуться к предыдущей версии проекта, которая работала без Docker.

---

## 📌 Информация о версиях

### Текущая версия (с Docker)
- **Коммит:** `0e84c57`
- **Описание:** Версия с Docker поддержкой и headless режимом браузера
- **Дата:** 30.05.2026
- **Что добавлено:**
  - Docker конфигурация (docker-compose.yml, Dockerfiles)
  - Автоматический headless режим в production
  - Полная документация по развертыванию
  - Обновленная обработка CORS и переменных окружения

### Предыдущая версия (без Docker)
- **Коммит:** `a9e4538`
- **Описание:** Рабочая версия до добавления Docker
- **Дата:** До 30.05.2026
- **Особенности:**
  - Запуск напрямую через npm
  - Браузер всегда видимый (не headless)
  - Без Docker контейнеризации

## 🔙 Как вернуться к старой версии

### Вариант 1: Временный возврат (для тестирования)

Этот способ позволяет посмотреть старую версию без изменения текущей ветки.

```bash
# Перейдите в директорию проекта
cd ~/projects/Luxee-website

# Переключитесь на старый коммит
git checkout a9e4538

# Теперь вы находитесь в состоянии "detached HEAD"
# Можете запустить старую версию для тестирования
```

**Запуск старой версии:**
```bash
# Backend
cd backend
npm install
npm start

# Frontend (в другом терминале)
cd frontend
npm install
npm run dev
```

**Возврат к текущей версии:**
```bash
# Вернитесь на main ветку
git checkout main
```

---

### Вариант 2: Полный откат (удаление Docker версии)

⚠️ **ВНИМАНИЕ:** Этот способ удалит все изменения с Docker!

```bash
# Перейдите в директорию проекта
cd ~/projects/Luxee-website

# Создайте резервную ветку с Docker версией (на всякий случай)
git branch docker-version

# Откатите main ветку к старой версии
git reset --hard a9e4538

# Если хотите обновить удаленный репозиторий (ОСТОРОЖНО!)
# git push origin main --force
```

**После отката:**
- Все Docker файлы будут удалены
- Код вернется к состоянию до Docker
- Браузер снова будет видимым

---

### Вариант 3: Создание отдельной ветки

Самый безопасный способ - работать с обеими версиями параллельно.

```bash
# Создайте ветку для версии без Docker
git checkout a9e4538
git checkout -b no-docker-version

# Теперь у вас есть две ветки:
# - main (с Docker)
# - no-docker-version (без Docker)

# Переключение между версиями:
git checkout main              # Версия с Docker
git checkout no-docker-version # Версия без Docker
```

| Аспект | Без Docker (a9e4538) | С Docker (0e84c57) |
|--------|---------------------|-------------------|
| **Запуск** | `npm start` в каждой папке | `docker compose up -d` |
| **Браузер** | Всегда видимый | Headless в production |
| **Зависимости** | Устанавливаются локально | Изолированы в контейнерах |

| **Развертывание** | Сложное, много шагов | Простое, одна команда |
| **Изоляция** | Нет | Полная изоляция |

## 🛠️ Настройка старой версии (без Docker)

Если вы вернулись к версии без Docker, вот что нужно настроить:

### 1. Установка зависимостей

```bash
# Backend
cd backend
npm install

# Frontend
cd frontend
npm install
```

### 2. Настройка MongoDB

Установите MongoDB локально:

**Ubuntu/Debian:**
```bash
sudo apt install -y mongodb
sudo systemctl start mongodb
sudo systemctl enable mongodb
```

**Windows:**
Скачайте с https://www.mongodb.com/try/download/community

### 3. Настройка переменных окружения

**Backend (.env):**
```env
PORT=5000
NODE_ENV=development
MONGO_URL=mongodb://localhost:27017/luxee
JWT_ACCESS_SECRET=your_secret_here
JWT_REFRESH_SECRET=your_secret_here
OPENAI_API_KEY=your_openai_key_here
```

**Frontend (.env):**
```env
VITE_API_URL=http://localhost:5000/api
```

### 4. Запуск приложения

```bash
# Terminal 1 - Backend
cd backend
npm start

# Terminal 2 - Frontend
cd frontend
npm run dev
```

### 5. Видимый браузер

В старой версии браузер будет открываться видимым окном. Это нормально для разработки.

Если хотите headless режим в старой версии:
```bash
# В backend/.env добавьте:
BROWSER_HEADLESS=true
```

## 🔍 Проверка текущей версии

Чтобы узнать на какой версии вы находитесь:

```bash
# Показать текущий коммит
git log --oneline -1

# Показать текущую ветку
git branch

# Показать все ветки
git branch -a

# Показать изменения
git status
```

**Если видите коммит `0e84c57`** - вы на версии с Docker  
**Если видите коммит `a9e4538`** - вы на версии без Docker

## 📝 Проверка наличия Docker файлов

```bash
# Проверьте наличие Docker файлов
ls -la | grep -i docker

# Если есть docker-compose.yml - это версия с Docker
# Если нет - это версия без Docker
```

## 🆘 Восстановление после проблем

### Если что-то пошло не так

```bash
# Отменить все локальные изменения
git reset --hard HEAD

# Вернуться на main ветку
git checkout main

# Обновить с удаленного репозитория
git pull origin main
```

### Если потеряли Docker версию

```bash
# Если создавали резервную ветку
git checkout docker-version

# Или восстановите из коммита
git checkout 0e84c57
git checkout -b main-restored
```
